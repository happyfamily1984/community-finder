# 부동산뉴스파인더 — 새 작업 세션용 인수인계 문서

이 문서는 "커뮤니티 파인더" 앱을 만들면서 정한 구조, 결정, 시행착오를 정리한 것이다.
새 세션에서 **같은 구조로 "부동산뉴스파인더"** (부동산 뉴스·정보를 모아 스레드용 글을 만드는 안드로이드 앱)를 만들 때 참고한다.
수집 대상 사이트 주소와 사이트별 선택자는 일부러 뺐다. 새 앱에서는 부동산 소스로 새로 정한다.

참고할 원본 저장소: `happyfamily1984/community-finder` (작업 브랜치가 기본 브랜치)

---

## 1. 사용자가 원하는 것 / 일하는 방식

- **결과물은 APK.** 웹앱(PWA) 말고 안드로이드 앱. 휴대폰에 직접 설치(사이드로드)한다.
- **수집은 클라우드에서.** PC나 서버를 켜두지 않는다.
- **토큰·비용을 아낀다.** 앱 동작에 유료 API나 Claude 토큰이 들면 안 된다. 무료 키(Gemini, Groq)와 휴대폰 내장 기능만 쓴다.
- **답변은 짧게, 결과 위주로.** 확인 단계가 길어지면 싫어한다.
- **출시는 시킬 때만.** 평소에는 "임시저장"만 한다: 커밋 메시지에 `[skip ci]`를 붙여 푸시하고, 로컬에서 빌드한 테스트 APK 파일을 대화로 보낸다.
- **테스트 APK는 매번 버전 번호를 올려서** 보낸다 (덮어쓰기 설치가 되도록). 예: `VERSION_CODE=121 VERSION_NAME=1.6.1-test`.
- 안 되는 게 있으면 **"GitHub 뒤져서 방법 찾아"** 라고 한다. 공개 코드에서 선택자·API 방식을 확인해 반영하면 좋아한다.
- 화면 캡처를 보내며 "이거 맞냐", "잘린다"처럼 짧게 피드백한다. 캡처를 보고 원인을 추정해 바로 고친다.
- UI는 전부 한국어.

## 2. 전체 구조

```
GitHub Actions (10분마다, 무료)              안드로이드 앱 (Kotlin + Compose)
┌──────────────────────────────┐  posts.json  ┌────────────────────────────────────┐
│ Node 수집기: 소스별 목록 수집 │ ───────────▶ │ 목록·필터·정렬·검색                 │
│ 점수 계산, data 브랜치에 게시 │ (raw 주소)   │ 글 미리보기(스캔 이미지)            │
└──────────────────────────────┘              │ 스레드용 내보내기(분할·모자이크·요약)│
                                              │ 백그라운드 확인 → 알림              │
                                              └────────────────────────────────────┘
```

- 공개 저장소라 Actions 무료. 수집 결과는 `data` 브랜치에 커밋 1개로 계속 덮어쓴다(히스토리 안 쌓임).
- 앱은 `https://raw.githubusercontent.com/<owner>/<repo>/data/posts.json`을 받는다. 캐시 회피용으로 `?t=분단위` 쿼리를 붙인다.
- 60일간 저장소 활동이 없으면 GitHub가 예약 워크플로를 멈춘다.

## 3. 클라우드 수집기 (Node 22, `src/`)

| 파일 | 역할 |
|---|---|
| `sources.js` | 소스 목록. HTML형은 `selectors`(row/title/link/views/comments/likes/exclude), 그 외는 `fetch` 함수 지정. `disabled`, `keepParams`(주소 정규화), `titleStrip` 옵션 |
| `parser.js` | cheerio로 선택자 기반 목록 파싱. `parseCount`("1.2만", "[12]" 등 숫자 표기 처리) |
| `fetcher.js` | HTML 가져오기, EUC-KR 자동 변환(iconv-lite) |
| `global.js` | JSON API / RSS·RDF 피드 수집 (`parseRss`는 북마크 수가 있으면 추천수로 사용) |
| `score.js` | 점수(0~100): 같은 소스 안 백분위(조회·댓글·추천) 평균 85점 + 분당 조회 증가 15점 |
| `crawler.js` | 수집 실행, 이전 상태와 병합(급상승 계산), 소스별 성공/실패 상태 기록, 24시간 지난 글 정리 |
| `crawl-once.js` | 1회 실행 후 `out/posts.json`(앱용 피드) + `out/state.json`(다음 실행용) 저장 |

- `.github/workflows/crawl.yml`: cron `*/10`, `data` 브랜치에서 이전 `state.json`을 읽고 → 수집 → `git init` 후 강제 푸시.
- 피드 형식: `{version, updatedAt, sources:[{id,name,board,url,color,status}], posts:[{id,source,title,url,views,comments,likes,score,viewsPerMin,firstSeenAt,rank,image?}]}`
- 테스트: `node --test test/*.test.js` (직접 만든 HTML/XML 조각으로 파서 검증).

**부동산 앱에 적용할 때:** 뉴스는 RSS가 있는 곳이 많으니 `fetchRss` 방식이 가장 안정적이다. 조회수·댓글이 없는 소스는 순위(최신순)로 점수가 매겨진다. 점수 기준을 "화제도" 대신 부동산에 맞게(키워드 가중치, 지역 등) 다시 정해야 한다.

## 4. 안드로이드 앱 (`android/`, 패키지 `com.communityfinder.app`)

빌드: AGP 8.10.1, Kotlin 2.1.21, Compose BOM 2025.05.00, minSdk 26, targetSdk 35, Gradle 8.14.3.

| 파일 | 역할 |
|---|---|
| `Feed.kt` | 피드 모델(`Source`, `Post`), 파싱(org.json), `FeedRepository`(받기·캐시·휴대폰 수집 소스 병합), 알림 조건 `matchesAlert` |
| `Prefs.kt` | SharedPreferences 래퍼 (알림 설정, API 키, 본 글 id 등) |
| `MainActivity.kt` | 탭(국내/해외/최근 본 글/설정), 목록 화면, 카드 UI, 알림 인텐트 처리(`pendingPost`) |
| `SettingsScreen.kt` | 설정(카드형 UI): 알림, 점수 기준 슬라이더, 키워드, 소스 선택, 번역 키, 확인 주기 |
| `OnboardingScreen.kt` | 처음 설정 안내: 알림 권한 → 배터리 최적화 제외 → 제한된 설정 허용 → 접근성 켜기 |
| `HotPostWorker.kt` | WorkManager 주기 작업(최소 15분). 새 글 중 조건에 맞는 것만 알림. 첫 실행은 기준점만 잡음 |
| `PageScanner.kt` | 보이지 않는 WebView로 페이지를 열어 전체를 한 장으로 캡처. 광고·댓글 숨김, 본문만 추리기, 번역, 작성자·본문·이미지 위치 분석 |
| `PreviewScreen.kt` | 글 미리보기(스캔 이미지 + "해당 글로 이동"), 모바일 주소 변환 |
| `ExportScreen.kt` | 스레드용 내보내기: 분할 이미지, 모자이크 스위치, 전체 화면 보기, 본문 요약, 갤러리 저장, 스레드에 올리기 |
| `ThreadsKit.kt` | 모자이크, 본문 자르기, **분할 위치 계산(`cutPoints`)**, 복사·저장·스레드 공유 |
| `Summarizer.kt` | 이미지 글자 인식(ML Kit 한국어) → Gemini→Groq 요약 |
| `Gemini.kt` / `Groq.kt` | 무료 키 기반 번역(`translate`)·자유 질문(`ask`). 모델 자동 선택, 한도 소진 시 쿨다운 |
| `Translator.kt` | 번역 순서: Gemini → Groq → 휴대폰 내장(ML Kit). 제목 번역 캐시 |
| `ImageTranslator.kt` | 사진 속 글자 번역: OCR → 번역 → 배경색으로 덮고 다시 그리기 |
| `ThreadsAutoService.kt` | 접근성 서비스: 스레드 앱에서 새 글 화면을 열고 본문 입력(게시 버튼은 안 누름) |
| `PostStore.kt` | 최근 본 글 저장 (JSON 파일) |
| `FmkoreaLocal.kt` / `RedditLocal.kt` | 클라우드에서 막힌 소스를 휴대폰에서 직접 수집하는 예시 (간격 제한·쿨다운 포함) |

- `.github/workflows/android.yml`: `android/**` 변경 시 테스트 + Roborazzi 스크린샷 + APK 빌드. **Releases 게시는 수동 실행에서 `release` 체크했을 때만.**
- 서명: 저장소에 넣은 공용 keystore로 debug/release 모두 서명 (어디서 빌드해도 덮어쓰기 설치 가능). 스토어 배포용 아님.
- `abiFilters arm64-v8a` (ML Kit 네이티브 용량 절감). APK 약 33MB.
- 단위 테스트는 JVM(JUnit) + Robolectric. 테스트 함수 이름은 영어로 (한글 이름은 빌드 환경 경로 문제로 실패).

## 5. 스레드용 내보내기 흐름 (새 앱의 핵심이 될 부분)

1. 글 선택 → `PageScanner`가 페이지를 캡처한다.
2. 본문 영역만 자르고(`cropRect`), 작성자 영역 모자이크(`mosaic`).
3. `split`: 세로로 나눈다. 규칙은 `cutPoints`에 있다.
   - 전체가 가로의 2배보다 짧으면 한 장.
   - 앞에서부터 한 장씩, 목표 길이(가로의 약 1.6배)에 가장 가까운 **여백**에서 자른다.
   - 여백 판정은 "가로로 훑었을 때 색이 바뀌는 지점 수"로 한다 (카드 테두리·회색 바탕이 있어도 여백으로 인식).
   - 사진 안에서는 자르지 않되, 한 장에 안 들어가는 긴 사진(글 캡처 이미지)은 사진 속 여백에서 자른다.
4. `Summarizer`: 분할 이미지에서 글자를 읽어(휴대폰 안) Gemini→Groq로 요약한다.
   - 형식: 첫 줄 핵심 한 문장 → 빈 줄 → 짧은 문장을 한 줄에 하나씩 → 마지막 줄 결말. 반말, 350자 이내, 해시태그·이모지 없음.
   - 스레드 본문에는 **요약만** 넣는다 (제목·출처 표기는 사용자가 뺐다. "출처 :" 문구가 있으면 노출이 줄어드는 것 같다고 함).
5. "스레드에 올리기": 이미지 여러 장 + 본문을 스레드 앱(`com.instagram.barcelona`)으로 공유 인텐트 전송. 본문은 클립보드에도 복사. 접근성 서비스가 켜져 있으면 본문을 자동 입력.

## 6. 겪은 문제와 해결 (다시 겪지 않도록)

**수집**
- 클라우드(데이터센터) IP를 막는 사이트가 있다(HTTP 403/430). 차단 우회(프록시, 위장)는 하지 않았다. 대안은 (a) 그 소스를 빼거나 (b) 휴대폰에서 낮은 빈도로 직접 받기.
- 일부 서비스는 로그인 없는 접근을 휴대폰에서도 막는다. 공식 API 등록이 필요한데 승인 절차가 있어 사용자가 직접 신청해야 한다.
- 글 주소에 순위·페이지 파라미터가 붙으면 같은 글이 새 글로 인식돼 알림이 중복된다 → 주소 정규화(`keepParams`).
- 목록 제목에 순위 숫자·댓글 수가 섞이는 사이트가 있다 → `titleStrip`, 댓글 요소 제거.

**페이지 캡처**
- 전체 페이지 캡처는 `WebView.enableSlowWholeDocumentDraw()`를 **첫 WebView 생성 전에** 호출해야 한다.
- 캡처 높이 = 화면폭 × scrollHeight / scrollWidth. 흰 배경을 먼저 칠한다. 최대 12,000px로 제한.
- 사이트 화면을 통째로 찍으면 광고·댓글·추천글이 섞인다 → 캡처 전에 JS로 숨기고, 사이트별 본문 선택자로 본문만 자른다.
- 가장 깔끔한 방법은 **본문 요소만 뽑아 "제목 + 본문"만 있는 페이지로 다시 구성**하는 것(`isolateJs`). 모바일 페이지 구조를 모르면 데스크톱 UA로 열어 본문을 뽑는다.
- 사진이 본문인 글은 사이트 화면 대신 "제목 + 원본 사진" HTML을 직접 만들어 캡처한다(`imagePostHtml`).

**번역 (해외 글)**
- 휴대폰 내장 번역(ML Kit)은 품질이 낮다. 사용자가 무료 키를 넣는 Gemini/Groq가 실사용 가능 수준.
- Gemini는 모델마다 무료 한도가 달라 첫 호출부터 429가 날 수 있다 → 후보 모델을 차례로 시도하고 성공한 모델을 기억.
- 모델 이름은 자주 바뀌므로 모델 목록 API로 고른다.

**안드로이드**
- 사이드로드 앱의 접근성 서비스는 "제한된 설정"으로 막힌다 → 앱 정보 화면 ⋮ → "제한된 설정 허용"을 안내(먼저 접근성에서 회색 항목을 한 번 터치해야 메뉴가 나타남).
- 접근성 서비스가 들어간 APK는 보안 기능이 설치를 막을 수 있다(사용자가 한 번 겪음).
- 백그라운드 확인은 최소 15분 간격. 배터리 최적화 제외를 안내한다.
- 알림을 누르면 원본 사이트가 아니라 앱 안 미리보기로 이동하게 했다(인텐트에 글 JSON 전달, `singleTop`).

**작업 환경 (Claude Code 클라우드 세션)**
- Android SDK가 없어서 세션마다 설치했다: cmdline-tools 내려받기 → `sdkmanager "platforms;android-35" "build-tools;35.0.0" "platform-tools"` → `android/local.properties`에 `sdk.dir`.
- 로컬에서 `assembleRelease`와 테스트 컴파일은 되지만, **Robolectric 실행은 네이티브 런타임 다운로드가 막혀 안 된다** → 화면·알림 테스트는 GitHub Actions에서만 돈다.
- KVM이 없어 에뮬레이터는 못 돌린다. 실제 동작 확인은 사용자의 휴대폰 캡처에 의존한다.
- 수집 대상 사이트는 세션에서 접속이 안 될 수 있다 → 수집 검증은 Actions 실행 후 `data` 브랜치 결과로 한다.
- Actions 아티팩트(스크린샷) 저장소도 접속이 막혀 직접 볼 수 없었다.

## 7. 부동산뉴스파인더에서 바꿀 것 (제안)

- **소스:** 부동산 뉴스 RSS, 정부·공공 발표(보도자료, 청약 일정, 실거래가 공개 데이터 등 공식 API/RSS), 부동산 커뮤니티 인기글. 공식 API·RSS를 우선한다.
- **분류:** 커뮤니티별 칩 대신 주제별(정책/청약/시세/금리/지역) 필터가 맞을 수 있다. 제목 키워드로 자동 태그.
- **점수:** 조회수 기반 화제도 대신 최신성 + 여러 매체가 동시에 다룬 주제(제목 유사도) + 키워드 가중치.
- **요약 프롬프트:** 유머 요약용 반말체 대신, 숫자(금액·금리·날짜·지역)를 정확히 살리는 정보형 요약으로 바꾼다. 수치를 지어내지 않도록 강하게 지시하고, 원문에 없는 전망·투자 조언은 금지.
- **저작권:** 뉴스 기사 본문을 캡처해 올리는 것은 커뮤니티 글보다 저작권 위험이 크다. 기사 캡처 대신 **요약 글 + 직접 만든 카드 이미지(제목·핵심 수치·출처 매체명)** 로 내보내는 방식을 먼저 검토한다.
- **그대로 재사용 가능한 것:** 클라우드 수집 구조와 워크플로, 피드 형식, 목록·설정·온보딩 UI, 알림 로직, Gemini/Groq 클라이언트, 요약 흐름, 분할 로직, 스레드 공유·접근성 자동 입력, 서명·버전 관리 방식.
- **필요 없는 것:** 해외 번역, 사진 속 글자 번역, 작성자 모자이크(뉴스에는 불필요) → 빼면 APK가 크게 줄어든다(ML Kit 번역·일본어 OCR 제거).

## 9. 스레드 계정 전환 (접근성 자동화) — 겪은 문제

`ThreadsAutoService.kt`의 `stepSwitch()` 참고. 흐름: 프로필 탭 → (이미 그 계정이면 종료) → 설정(톱니바퀴) → 맨 아래로 스크롤 → 로그아웃 → 확인 창 로그아웃 → 저장된 계정 목록에서 계정 선택.

- **화면 좌표를 직접 누르는 예비 동작은 넣지 말 것.** 스레드 탭 대신 휴대폰 내비게이션 바(최근 앱/뒤로)를 눌러 엉뚱한 화면으로 넘어갔다. 찾은 요소의 위치만 누르고, `tap()`에서 내비게이션 바 영역(`WindowInsets.Type.navigationBars()`)은 거부한다.
- 스레드의 탭·아이콘은 `isClickable`로 표시되지 않을 수 있다. 이름표(`프로필`/`Profile`) → id에 `profile` 포함 → "아래쪽에서 4개 이상 나란한 줄의 맨 오른쪽" 순으로 찾는다.
- 실제 화면 구조를 볼 수 없으므로 **전환 기록**(`ThreadsAuto.log`, 설정의 "전환 기록 보기")에 단계와 화면 요소 목록을 남겨, 사용자가 복사해 보내주면 그걸 보고 고친다.
- `android:canPerformGestures="true"`를 추가하면 접근성 서비스를 다시 켜야 할 수 있다.
- **스레드에서는 `findAccessibilityNodeInfosByText`가 동작하지 않는다**(가상 노드). 화면 판별·버튼 찾기는 전부 노드 트리를 직접 훑어서(`walk`) 글자를 모아 비교해야 한다.
- 탭은 `ACTION_CLICK`(부모 클릭)에는 반응하지 않고, `dispatchGesture`로 요소 중심을 실제 터치해야 넘어간다.
- 화면이 계속 바뀌는 앱이라, 이벤트마다 타이머를 다시 잡으면 영원히 실행되지 않는다. 반복 실행은 한 번만 시작해 둔다.
- 전환 시작 시 `FLAG_ACTIVITY_CLEAR_TASK`로 스레드를 홈부터 열고, 탭 바가 안 보이면 뒤로가기로 빠져나온다.
